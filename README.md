# Sparky 中文学习伙伴

为 2–5 岁儿童设计的本地原型。C 是唯一面对儿童的双语伙伴。A 短练习和 B 故事或听辨活动向 C 提供目标、上下文和允许的动作。课程配置和运行代码各自维护。

## 运行

在项目目录使用 Python 3.10 或以上版本和带 SQLite JSON 支持的 Python 发行版。服务端使用标准库。

```sh
python3 -m sparky check
python3 server.py --port 8765
```

打开 [本机小屋](http://127.0.0.1:8765/)。首次使用时允许浏览器使用麦克风，或直接输入一句话并按回车。例如说「我想画画」开始故事，说「练一句中文」进入短练习。故事中可以插问词义、切入同目标短练习、暂停和恢复。[独立家长空间](http://127.0.0.1:8765/parent)提供独立儿童档案、分类学习记录、偏好确认与删除。设置环境变量 `SPARKY_PARENT_PIN` 后，新建档案及家长数据接口会要求这个 PIN。服务只监听本机。家庭身份通过该浏览器的本机 Cookie 关联，使用同一个浏览器可以续玩。

## 内容怎么配

默认用英语自然交流，由大脑结合当前意图、理解程度、情绪、近期对话和学习目标，判断何时适合引入中文。不设语言比例，也不把“提到某个词”直接当成教学指令。明确要求说英文或中文时，保存为当前儿童档案的语言偏好，后续轮次继续遵守；可要求恢复双语交流。切换偏好不推进活动，也不产生学习证据。

编辑 `curriculum/conversation.json`，每项填写目标词 `word`、中英文线索 `cues`、接话例子 `offer` 和 `follow`。这些是大脑可参考的素材，不要求照读。没有可用文本模型时，默认只给出简短英文兜底，不靠关键词自动插入中文教学。明确选择中文交流时保留中文例句兜底。闲聊示范不会被计为孩子已掌握该词。

课件的 `prompts_en` 提供英文活动说明，`prompts` 保留中文版本。中文听辨目标和请求的中文示范仍保留原文；听辨提示不得透露目标的英文答案。旧活动快照没有 `prompts_en` 时使用通用英文说明，不改变已保存的目标与进度。服务重启后代码与新课件生效。

| 配置 | 由谁使用 | 写什么 |
| --- | --- | --- |
| `curriculum/goals.json` | 教研 | 可跨主题复用的能力标识与中文名称。例如多个主题都可记录「做出有意义的选择」。 |
| `curriculum/templates/*.json` | 活动设计 | A 或 B、步骤顺序、每一步接受有意义回应或完整目标表达、可用选项范围、是否保存选择，以及听不清后的处理。 |
| `curriculum/lessons/*.json` | 内容编辑 | 本课采用的模板、目标对应关系、场景问题、词条、中英文别称、目标句、可复用句式，以及可选的听辨目标。 |

例如颜色课把「红色」「蓝色」绑定到目标句式 `这是{zh}的`，会生成「这是红色的」「这是蓝色的」两个可接受的表达。`我选{en}` 属于有意义的选择句式。两类回应分别产生目标句表达证据和选项参与记录。每个词条的 `forms[0]` 是伙伴实际使用的示范句。

新增同类主题时，复制一份课件，修改文件名及同名 `id`，填写目标、问题和词条。需要另一种教学方法时可以添加步骤模板，例如 `listen_find` 用每一步的 `expected` 引用课件中的目标词条，只有选中指定目标才推进。卡片上的点选可记录为听辨任务的选择结果。生活中的身体动作需要其他观察依据。

运行 `python3 -m sparky check` 检查引用、句式、词条歧义和步骤。重启服务后，新活动使用最新配置。已有活动保存整份内容和规则快照，恢复时继续使用当初的版本。修改已发布内容时递增对应的 `version`。

## 一轮互动怎么走

1. 网页把文字、点击或浏览器语音识别结果连同事件 ID、当前版本发给 C。
2. C 预演合法活动动作，把执行后状态、教学约束、会话摘要、近期原文和送达情况一起交给主模型。主模型一次提出动作与自然回复。明确语言控制和低质量输入保留本地路径；模型不可用时使用已校验的本地回复。
3. 应用校验动作、词条和进度版本，在一个 SQLite 事务里提交活动快照与学习观察。同一事件重试只生效一次。
4. 网页显示已确认的场景并可调用浏览器语音合成。播报事件记录开始、完整播放和中断，迟到的回报按回复 ID 与播放次数过滤。上一次提示实际播完后复述示范句可以记为模仿。提示送达不完整时保留「得到帮助」的证据。
5. 家长摘要按目标和观察类型汇总。英语选择、点击、短词、完整句、沉默、拒绝和输入不清分别记录。数据库位于 `.data/sparky.sqlite3`。近期原文在进程内短期保留，至少供给最近 8 轮；摘要未完成时保留未压缩轮次（最多 32 轮）。较早对话由后台压缩成话题、明确事实与未完成约定，摘要保存在数据库。默认不存录音或完整逐字稿；数据库另存最新回复、活动进度、语言偏好、近期拒绝/示范事件、学习观察和最近 100 轮结构化诊断。删除档案会级联清除，忘记偏好也会清理摘要及近期上下文并阻止迟到摘要写回。

## 语音与模型

### Cascade 主链路

当前实现为「录音 → OpenAI ASR → C 运行时与 A/B 活动 → 校验提交 → OpenAI 语音合成 → 播放回报」。它不调用 GPT-Live；既有 Live 测试入口独立保留。A/B 仍是活动模块，本次不改变教学规则或引入多 agent。

首次安装和启动：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --cascade
```

启动时隐藏输入 OpenAI API key，或读取已有的 `OPENAI_API_KEY`；密钥只保留在服务端，不写入项目文件或返回浏览器。默认仍监听 [本机小屋](http://127.0.0.1:8765/)。若旧服务占用端口，先停止旧服务，或加 `--port 8770`。后续启动只需最后一条命令。可用 `--db` 指定独立的成人测试数据库。

页面点击「开始说话」，根据本地音量与背景噪声估计检测停顿，也可点击「说完了」。可选择约 1 / 1.5 / 2.2 秒的等待时间；短语音至少多等至约 2 秒，给思考停顿留空间。每段最多 20 秒、3 MB。勾选「连续对话」后播完会自动继续接听，默认关闭。「打断并说话」取消旧播放并开启新录音，「停止语音」或离开页面会释放麦克风并取消自动接听。支持文字输入，经相同教学后台处理后合成声音。

模型默认值（2026-11-23 查阅官方文档）：

| 环节 | 默认模型与接口 | 可配置项 |
| --- | --- | --- |
| ASR | `gpt-transcribe`，`/v1/audio/transcriptions`，同时提供中英文语言提示 | `SPARKY_ASR_MODEL`，替换型号须支持相同协议 |
| 文本大脑 | `gpt-4.1`，Chat Completions，沿用现有动作提议接口 | `SPARKY_MODEL`、`SPARKY_MODEL_URL`、`SPARKY_MODEL_KEY` |
| 语音合成 | `gpt-realtime-2.1-mini`，Realtime WebSocket，仅朗读确认后的文本，默认 `marin` 音色 | `SPARKY_TTS_MODEL`、`SPARKY_TTS_VOICE`，须兼容 Realtime 音频输出 |

官方当前推荐 [gpt-transcribe](https://developers.openai.com/api/docs/guides/speech-to-text) 进行分段录音转写；[语音合成指南](https://developers.openai.com/api/docs/guides/text-to-speech) 指明旧 Speech API 模型正在弃用，新推荐型号需走 Realtime API，不能直接填入 `/v1/audio/speech`。这里使用 Realtime 作为独立合成器：不发送麦克风、课程上下文或工具，只发送后台确认的文字。合成转写与原文不一致时不播放，避免改写教学示范。

如果已配置自定义 `SPARKY_MODEL_URL`，启动不会把 OpenAI key 自动发送到该地址；须自行提供该服务的模型与密钥。否则 `--cascade` 配置 OpenAI 文本接口；默认文本型号优先兼容现有 `temperature` / `max_tokens` 协议，换模型时需检查参数支持情况。已知活动答案仍由规则判定证据类别；配置了模型时可同时自然改写回应。ASR/TTS、对话与后台摘要按实际调用收费。

当前仍按轮次工作：录音结束后上传 ASR，文本决策提交后根据长度选择整段或逐句合成。长回复每句收齐音频并核对原文后即可播放，播放时预取下一句，最多并行准备一个后续句；首句不必等待整条回复的音频生成。引号内教学示范保持完整。短回复一次生成完整音频。仍不是端到端流式或全双工，ASR 也仍是录完上传；真实儿童混说、轮次结束和实际延迟改善需实测。ASR 未返回置信度时不伪造置信分数；现阶段没有说话人识别或发音评分。

活动操作成功后即保存，打断声音不回滚活动。排队中已取消的轮次不再提交；已经送达后端的操作仍可能完成。ASR/TTS 可在客户端取消并丢弃迟到结果，但服务端已有上游请求可能运行至完成或超时。按回复 ID、分句编号及播放尝试记录 `started` / `complete` / `interrupted` / `failed`；下一轮上下文包含实际送达情况。浏览器拒绝播放或合成失败会保留文字。

短回复（最多两句、加权长度不超过 160，中文字符计 3）一次合成和校验，减少重复建连及句间等待；较长回复按完整句合成，播放本句时提前准备下一句。该阈值是可调整的启发式，不是延迟保证。逐句播放时，中文示范所在句播完即计为完整示范；整段播放时只能确认整段播完，若中途打断则保守地把各句记为未完整送达。两种模式都校验语音转写与确认文本一致，额外开场白也会被拦截。

音频仅在内存中处理，本机不写录音文件；音频发送到 OpenAI ASR，文本和有关上下文发送到配置的文本服务，确认回复发送到合成服务。先用成人模拟语音联调。真实儿童数据使用前需按项目要求确认服务端数据设置。

验证命令：

```sh
.venv/bin/python -m unittest discover -s tests -v
node --test tests/*.test.cjs
```

测试通过可控的 ASR/TTS 协议样例验证格式、权限、状态与播放生命周期，不消耗真实模型额度。实际 key 的模型权限、真实音频质量和设备播放体验需要联网联调。

### 第二层大脑、诊断和真实模型评测

核心 System Prompt 由 `sparky/prompts/core.txt`（角色与交流原则）和 `sparky/prompts/protocol.txt`（上下文字段、动作与输出协议）拼接。调试页展示拼接后实际使用的全文；独立 Live 实验只复用交流原则。后台摘要使用 `sparky/prompts/summary.txt`。修改后重启服务生效。`sparky/planning.py` 预演合法工具及执行后状态，校验模型动作与必要教学原文，表达不合格时最多请求一次修正，再退回有效模板。模型调用都在数据库写事务外，A/B 仍是按需调用的活动能力。

课件 `capabilities.A/B` 描述各模式实际能做什么，连同合法动作一起交给模型，区分自然活动请求与过去经历/兴趣分享。新课件版本保留在活动快照里，恢复旧活动仍使用原快照。当前绘画能力是选色和讨论画面的想象活动，没有数字画板。

启动后打开同一端口的 `/debug`（例如 `http://127.0.0.1:8770/debug`），选择当前浏览器所属档案；若配置家长 PIN，需要输入 PIN。面板显示本轮动作、模型错误类型、ASR/大脑/逐句 TTS 耗时、客户端首音与总耗时、分句送达情况、会话摘要以及实际核心 Prompt。默认不记录逐字稿；仅开发测试需要时以 `SPARKY_DEBUG_TRANSCRIPTS=1` 启动。调试页不显示密钥或模型推理过程。

真实模型评测使用 `evaluations/conversations.json` 中的合成对话和临时数据库，不改动儿童档案：

```sh
.venv/bin/python -m sparky.evaluate                 # 仅查看场景，不调用模型
.venv/bin/python -m sparky.evaluate --run --output .data/baseline.json
.venv/bin/python -m sparky.evaluate --run --compare .data/baseline.json --output .data/after.json
```

运行评测需要在该终端设置 `OPENAI_API_KEY` 或现有 `SPARKY_MODEL*` 配置，会调用真实文本模型。报告保存动作/语言检查结果、回复、错误及耗时，用于前后对比。语气、中文引入时机和相关性仍需人工审阅；该评测不测真实 ASR/TTS 音质与语音端到端延迟。

额外活动表达用例：加 `--cases evaluations/activity-paraphrases.json`，覆盖画画/涂画请求、否定、引用、过去经历、未来计划，以及暂停恢复；检查活动是否真正执行，并避免误启动。

### GPT-Live 成人模拟测试

在项目目录运行以下命令。终端会隐藏输入的 OpenAI 项目密钥，也可读取已设置的 `OPENAI_API_KEY`。

```sh
python3 server.py --live-test
```

打开 [成人语音测试页](http://127.0.0.1:8766/)，允许麦克风后直接开口。页面显示「GPT-Live 已连接」后，说「我想画画」，然后试试只答一个「蓝」、停顿后补充、在伙伴讲话时插话。模型通过 WebRTC 收发声音，课程请求交给本机教学后台。说「关闭麦克风」或切换到后台会停止采音，输入「开启语音」可以重连。测试学习记录使用独立数据库。首次联调使用成人模拟语音；接入真实幼儿个人数据前，需确认项目的数据保留设置满足 [OpenAI 未成年人使用指引](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance)。

### 浏览器语音

儿童页自动尝试启动浏览器语音识别。允许麦克风后可开口说话，伙伴播报完会再次聆听。识别端支持情况和联网需求取决于浏览器。语音未启动时可打字回车，输入「开启语音」重试。说「关闭麦克风」结束聆听。后台标签页会停止录音和播报。

默认使用本地规则，适合验证活动流程。接入一个兼容 Chat Completions 的服务后可运行自由对话。服务端读取以下环境变量。选择外部模型时，它会收到当前输入和本轮相关上下文。

- `SPARKY_MODEL_URL` 为完整的 HTTP 接口地址，例如 `http://127.0.0.1:11434/v1/chat/completions`。
- `SPARKY_MODEL` 为该服务实际提供的模型名称。
- `SPARKY_MODEL_KEY` 为可选的服务端访问密钥。

接口失败或输出动作无效时，伙伴回到澄清流程。模型理解出的自由表达可推进允许的任务，独立中文表达的记录依据配置的目标句和实际帮助情况。

### 陪伴、安全与家长设置

`/parent` 可设置英语母语表达水平（尚在发展 / 较熟练 / 未知）；中文为目标语言。模型根据家长信息选择情境示范或简短英文解释，明确语言请求始终优先。普通兴趣可以由家长确认、删除；后台从较短对话开始保存摘要，家长可以查看和清除。摘要是模型生成的线索，不等于经过人工确认的永久记忆。

危险、强烈情绪和伤害披露可选择 `support`，保存并暂停已有活动，不计为学习表现；恢复需要新的明确意愿。少数明确危险表达有不依赖模型的应急回复，其余依赖模型理解，不能视为完备的安全分类器。系统不能报警或通知家长。披露回应原则参考 [NSPCC](https://learning.nspcc.org.uk/child-abuse-and-neglect/recognising-and-responding-to-abuse)：接纳、不责备、不诱导细节、不承诺保密、寻找安全的大人。

打断时浏览器立即停播并中止旧 HTTP 请求；`/api/cancel` 让尚未提交的旧轮次失效，新轮次重新同步进度。已经提交的活动不回滚；已发出的上游请求仍可能运行并计费。现在支持按钮打断和可关闭的连续接听，尚未实现播放时自动识别孩子插话，不是全双工。

### 人工评审和模拟小朋友

`evaluations/golden-review.json` 是 10 段**待人工审核草稿**，不是人工金标准。先由人修改标准、示例并填写每段 `review.reviewer`、`review.status=approved`，再执行：

```sh
.venv/bin/python -m sparky.simulate --run
```

模拟器使用临时档案，由虚构小朋友根据上一轮实际回复继续对话，另附模型评审建议。尚未全部人工审核时不会调用模型；模型评审不替代人工安全和对话质量判断。

### Cloudflare 临时试用

先运行官方 `cloudflared tunnel --url http://127.0.0.1:8780 --protocol http2`，获得 HTTPS 地址后启动：

